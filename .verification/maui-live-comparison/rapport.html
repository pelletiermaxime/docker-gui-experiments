Docker GUI experiments / C# / Linux GTK4

A live Docker list
in .NET MAUI.

Built-in Entry, Button and virtualized CollectionView controls, background Docker SDK requests, search and manual Refresh. Same four display fields, all container states, no polling or Docker mutations.

This uses MAUI's experimental Linux GTK4 backend. It is developed in Microsoft MAUI Labs and is not an officially supported MAUI platform. These measurements describe this backend, not standard Windows/WinUI or Mac Catalyst. The native window loaded the same 14 full container IDs as the current read-only reference.

Native windows and input

The inspected search capture records the typed query and filtered rows. Refresh is observed through native keyboard activation of its button and an additional successful SDK-load log: 1 before, 2 after. The observation process exited: True.

Scope and limitations

  • MAUI Controls 10.0.110; GTK4 backend 0.1.0-preview.13.26512.5; .NET SDK 10.0.402; Docker.DotNet.Enhanced 4.3.3. Packages are locked.
  • Four-second warmup, twenty seconds at idle, 500 ms process samples, one owned X11/XWayland window at a time, 1,000 × 680 client surface. No strace during these measurements.
  • RSS includes resident shared pages; PSS apportions them. Neither includes the compositor's memory or all GPU allocations. GTK's default graphics path is retained; mapped library presence does not prove a particular adapter.
  • These runs happened after the original framework comparison. The inventory ID digest is 9b3587c9a02aefc52a6ad2b5c04fb1ba6e3615c0673b13bf87ce0bc1db2ff931; current inventory equivalence does not make timing or environmental conditions contemporaneous.
  • SDK responses are fully buffered before the 20,000-row limit. Requests have a ten-second deadline; failed loads preserve the last successful rows. No Docker CLI or snapshot is used inside the app.
  • The experimental backend emits GTK layout/theme warnings. Some long image names wrap despite MAUI truncation settings, and the native layout differs from the other prototypes. Screenshots retain these issues; no backend patches were applied.
  • No Windows, macOS, busy-output, large-inventory, energy or interactive-throughput measurements. No automated test suite was added or run.

Code-quality assessment

The app uses native MAUI controls, one focused page and a small platform bootstrap. Async Docker work runs off the UI thread, refreshes cannot overlap, and cancellation follows window closure. This is a small demonstration, not a complete Docker endpoint manager. It deliberately omits a view-model framework and additional abstraction layers; the remaining Linux risk is chiefly the experimental handler/backend behavior.
